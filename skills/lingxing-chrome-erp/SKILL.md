# 领星 ERP（Chrome）

复用用户指定的 Chrome 及已登录领星会话，以当前可见界面为准。租户、权限和版本会影响菜单、字段和报表能力；历史路径仅作导航线索。

## 先按交付目标分流

| 用户请求 | 执行到哪里 |
| --- | --- |
| 导出、下载数据、准备周报素材 | 设置筛选 → 原生导出 → 下载文件 → 返回保存位置，到此结束。 |
| 生成周报、总结操作、分析数据 | 先取得必要数据，再做任务所需的计算和撰写；已有适用文件直接使用。 |
| 修改广告、商品或业务设置 | 按对应业务流程执行，确认授权范围并回读操作结果。 |

当前请求和已确认偏好优先。导出原始文件与后续分析是两个阶段；分析、表格制作技能的核验要求不能自动成为导出前置条件。

按需读取参考，不默认加载全部手册：

- 导出路径或下载故障：读 [导出操作手册](references/export-workflows.md) 中对应模块或故障段落。
- 分析或业务操作：读 [任务操作手册](references/task-playbooks.md) 中对应章节。
- 模块不明、入口或控件变化：再读 [帮助中心导航](references/help-center-map.md)，必要时搜索官方帮助中心 `https://www.lingxing.com/help/index`。熟悉的导出流程不先查帮助。

## 默认快捷导出

准备素材时，优先复用用户提供或上下文已有且范围已明确适用的原表，只补缺失项。适用范围从用户说明或已知导出条件判断，不为复用而开表核验；用户明确要求重新导出时按新请求执行。

1. 从请求和上下文取得报表类型、店铺/站点、日期、维度及保存位置，只问会影响导出的缺失条件。保存位置未指定时使用浏览器实际下载目录，不为选目录中断任务。
2. 优先复用相关标签页或已知入口。一次应用所需筛选，确认控件已生效且加载结束后直接导出；这是操作确认，不是读取指标对账。不要刷新已设好条件的页面。
3. 只导出用户所需的报表与维度。未指定而又不影响目标时保留页面默认粒度；只有影响交付含义的歧义才询问。不要为证明完整性追加父 ASIN、MSKU、周/月、日报或汇总版本。
4. 页面支持目标产品筛选时直接使用；**只能整店导出时，原样交付整店文件，说明包含其他产品，不打开文件筛选产品。** 页面时间粒度不足以精确表达请求时，取得覆盖请求的最小可导出窗口，并说明实际范围，不在导出阶段裁切内容。
5. 多份异步报表连续提交，利用后台生成时间处理下一份，之后集中下载。用本次任务 ID/名称、条件和下载状态在工作上下文中避免重复，不另写审计文件。同一浏览器由一个执行者控制。
6. **完成标准：对应本次请求的文件已下载完成，且有可交付的文件位置。** “正在创建”或“生成成功”本身不等于已下载。必要时只检查最终文件存在且不再是临时下载文件，不打开文件检查内容。
7. 用户指定目录时将原文件保存或复制过去；没有要求时保留原格式和文件名，不覆盖旧文件。返回路径后结束导出阶段。

默认不做以下工作：

- 打开 Excel、扫描表头或工作表、统计行数、核对金额/日期覆盖/ASIN 覆盖、与页面或其他报表对账、计算 SHA256。
- 生成产品筛选副本、清洗 CSV、索引 Excel、截图证据、审计报告、ZIP 或额外备份包。
- 为核验重复点击下载、遍历不同视图、补采其他周期，或自动调用历史分析、核验、打包脚本。

用户明确要求这些交付时再执行。必要的界面读取或定位截图不作为额外交付证据。

## 导出失败继续处理

用户偏好是继续排查直到取得数据，不因一次失败就结束。先看实际现象，再按 [导出操作手册](references/export-workflows.md) 排查下载延迟、保存位置、任务创建日期筛选、新旧下载中心、日期控件和页面支持的恢复入口。保持请求范围；必要时按平台限制拆分日期或批次。

复用已有任务，不盲目重复提交；逐步延长刷新间隔，单次等待不超过 60 秒。状态长期不变时改查具体原因或其他受支持入口，不无限空刷。同一路径无变化的重复调用不算新尝试。

原生导出确实不可用时，可继续提取同范围可见页面表格，保存为明确标注“页面提取”的文件；保留实际取得的范围，不冒充原始报表或全量导出。这不触发内容核验或报告制作。若当前请求明确只接受领星原生报表、不接受页面提取，则继续排查原生路径，无法取得时说明阻点，不擅自替换格式。

确实需要登录、验证码、权限或平台恢复时，说明具体阻点及已取得文件；页面确认无可导出数据时说明实际结果，不伪造空表。不要将某次历史失败认定为永久限制，也不要绕过浏览器安全限制或权限。

## 通用浏览器规则

- 使用当前浏览器工具提供的文档和受支持操作，不复制历史工具 API、坐标或过期选择器。仅在状态发生变化或操作分支需要时重新读取相关界面，避免反复抓取整页。
- 店铺选择须在“已选店铺”或当前已选标签中生效；日期、国家、币种和来源以当前控件为准，不继承旧任务筛选。
- 用户未登录时请其登录；不要读取或暴露密码、Cookie、local storage、认证令牌，也不猜测接口或提取凭据调用私有 API。
- 修改前记录相关当前状态，按授权的最小范围操作；批量修改在界面支持时先用一条记录试行。该试行要求不适用于报表导出。
- 导入使用当前官方模板，保留格式，提交前预览错误。业务写入后确认实际结果，不把“无需导出数据核验”扩大为跳过写入确认。

## 业务变更的授权

以下动作需要明确的范围授权；沿用本次会话已给出的授权，不为同一明确范围反复确认。缺少授权或最终范围未定时，先准备可审核结果，再请求确认：

- 提交、审批采购/委外单、付款、发票、货件、补货、物流单或库存调整。
- 发布、修改、启停或批量编辑 Listing、价格、促销、广告活动/预算/竞价或自动规则。
- 发送买家消息、邮件、评价请求或 RMA 操作。
- 修改授权、用户、角色、权限、全局设置、汇率或集成。
- 删除、作废、禁用、覆盖记录或导入业务数据。

只读查询、筛选、创建导出任务和下载文件无需额外确认。发送或上传数据到外部位置仍须符合用户授权。

## 其他模块路由

- 初始化与权限：设置 → 店铺/广告授权、邮箱、部门/角色/用户、仓库和业务配置。
- 产品与销售：产品 → 产品资料/新品开发；销售 → Listing、订单、促销。区分本地 SKU 与线上 MSKU。
- 供应链：采购/FBA → 计划/订单/委外；仓库 → 库存/收发货/海外仓；物流 → 报价/头程/渠道/报关。
- 客服与财务：客服 → 消息/售后/RMA/评价；财务 → 结算利润/账单/成本/存货核算/资金；统计/BI → 看板和分析。
- 广告修改：先明确站点、广告类型、活动或目标及当前设置，再执行对应业务流程。

## 完成回复

导出任务只列已下载文件、保存位置、必要的范围说明和未取得项；页面提取文件单独标明来源。无需附上条数、金额、核验声明或过程流水账。分析或业务变更按用户要求交付结果，未完成的操作不得宣称成功。
